# 3 机器人平台：T4 与 Zvalley 生态

本章涉及的尺寸、重量、关节限位和电气参数来源于厂家手册及实测记录。暂时缺少的数据应明确标记为待补，避免根据其他平台的参数进行推测。

## 3.1 T4 平台参数与初步检查

| 参数 | 查阅途径 | 关注原因 |
| :--- | :--- | :--- |
| **身高、体重** | 厂家手册（私有子模块） | 赛前检录指标；重心高低决定步态参数 |

| **传感器清单** | 手册与实物核验 | 决定定位算法方案，同时关系到检录合规性 |
| **电池与续航** | 手册与实测记录 | 决定单场比赛换电频度与备用电池数量 |

### 核对手册与实物

接手平台时，建议完成以下测量并将结果存入队内平台档案：

1. 将机器人摆放为标准零位姿态，使用卷尺测量直立高度，使用台秤称量整机重量。
2. 逐个关节手动转动至物理限位，记录正负方向的最大活动角度。
3. 开机执行 `nvidia-smi` 和 `top`，记录空载运行时的 CPU、内存与显存占用。
4. 满电状态运行标准步态，记录母线电压下降曲线与有效续航时长。
5. 将测量数据整理归档，供后续调试与赛季交接使用。

## 3.2 关节与自由度

双足人形机器人的单腿通常配置 6 个自由度：髋关节 3 个（前后摆动、侧向摆动与轴向旋转）、膝关节 1 个、踝关节 2 个（前后俯仰与侧向摆动）。这些关节共同决定下肢的支撑、摆动与落脚控制能力。

| 部位 | 自由度数量 | 异常时的故障表现 |
| :--- | :--- | :--- |
| **髋（前后）** | 1 | 步幅受限，无法正常迈步 |
| **髋（侧向）** | 1 | 重心横移受阻，站立失衡 |
| **髋（旋转）** | 1 | 原地转向困难，踢球方向偏斜 |
| **膝** | 1 | 屈膝下蹲受限，无法执行起身动作 |
| **踝（前后）** | 1 | 触地缓冲失效，行走易向前倾倒 |
| **踝（侧向）** | 1 | 侧向抗扰动能力下降，受碰易倾翻 |

> [!NOTE]
> 关节零位由机械标定确定，编码器读数必须与标定位置严格对应。更换电机或编码器、经历严重跌落，或发现关节位置异常时，必须按照厂家规范重新执行零位标定。

## 3.3 IMU 与姿态估计

IMU（惯性测量单元）主要采集并输出以下运动数据：

- **三轴角速度**：测量机体转向与倾晃的动态角速率。
- **三轴加速度**：测量重力加速度分量与外部碰撞冲击。
- **解算姿态角**：芯片或滤波算法解算得出的横滚角（Roll）、俯仰角（Pitch）与偏航角（Yaw）。

在控制系统中，IMU 常用于机体姿态反馈和跌倒状态检测。姿态估计输出用于调节踝关节与髋关节的目标角度；当机体姿态超过安全阈值时，保护逻辑将触发停机或姿态恢复动作。

| 误差来源 | 表现特征与处理方法 |
| :--- | :--- |
| **零偏** | 静止状态下角速度输出非零，积分几秒便漂移数度。系统上电后先保持静止采样数秒计算均值，扣除零偏后再进行积分。 |
| **温漂** | 传感器工作温度变化导致零偏发生漂移。在规定预热时间后检查，必要时引入温度补偿模型。 |
| **振动干扰** | 机器人双足踏地产生高频冲击，加速度波形伴随毛刺并导致姿态跳变。引入低通滤波器处理原始数据。 |
| **坐标系差异** | 芯片安装方向与机体坐标系不重合。记录物理安装朝向，在程序接口层统一做固定坐标旋转。 |

## 3.4 足式里程计与误差来源

双足人形机器人缺少连续滚动的车轮，里程计依靠运动学推导：通过触地传感器判断支撑相脚掌，应用正运动学（Forward Kinematics）将下肢关节编码器角度解算为脚掌相对机体的位置，再逆向推断机体相对地面的位移增量。

| 误差来源 | 表现特征与缓解方法 |
| :--- | :--- |
| **脚掌打滑** | 实际位移小于关节位移推导值。结合视觉标线观测修正累计漂移。 |
| **足底柔性形变** | 橡胶脚垫受力产生弹性形变，导致接触点解算偏差。利用触地开关信号进行接触状态校准。 |
| **关节零位偏差** | 机械零位存在小角度偏差，长距离移动会导致轨迹明显偏斜。定期执行关节零位标定。 |
| **时间戳不同步** | 图像采集时间与关节反馈时间存在偏差，导致融合解算错位。系统各节点统一使用同一时间基准。 |

足式里程计能够提供高频、连续的短时位移估计，但误差会随时间线性累积；视觉观测可用于消除长期位置漂移，二者融合机制参见第 4 章。

## 3.5 机载软件结构与运行频率

机载软件由多个协同进程组成。不同模块对实时性的要求存在差异，需要配置不同的调度频率：

| 模块 | 典型运行频率 | 输入数据 | 输出结果 |
| :--- | :--- | :--- | :--- |
| **相机驱动** | 30–60 Hz | 传感器数据流 | 原始图像帧 |
| **视觉检测** | 15–30 Hz | 图像帧 | 足球、球门、机器人边界框与类型 |
| **定位系统** | 10–30 Hz | 视觉观测特征、里程计增量 | 机体在球场中的全局位姿 |
| **决策系统** | 5–20 Hz | 全局位姿、球体位置、裁判盒指令 | 目标行为与目标速度 |
| **运动控制** | 100–500 Hz | 目标速度、IMU 姿态反馈 | 各关节力矩与目标角度指令 |

## 3.6 电气系统与通信接口

电源配电、通信总线和硬件急停回路需要与软件接口协同核验。接线错误可能损坏驱动板或引发设备安全问题，电气维护必须严格遵循操作规程。

| 模块 | 功能说明 | 操作注意事项 |
| :--- | :--- | :--- |
| **动力母线** | 为关节伺服电机供电，高电压大电流回路 | 严禁带电插拔；极性接反会损毁驱动电路 |
| **逻辑电源** | 为机载工控机、激光雷达/相机与传感器独立供电 | 逻辑电与动力电隔离走线，避免电机启停引起系统掉电 |
| **CAN / EtherCAT 总线** | 负责工控机与关节执行器之间的高频通信 | 终端匹配电阻必须正确，过长线缆易造成高频丢帧 |
| **以太网链路** | 连接视觉相机、机载计算单元与调试主机 | 配置为与赛场裁判盒处于同一局域网网段 |
| **硬件急停回路** | 物理硬切断动力供电回路 | 独立于控制软件；机载程序失响应时急停必须依然可靠切断动力 |

### 接线与上电检查流程

1. 拔插任何接插件前，必须先断开高压动力电源。带电插拔通信线与电机线是造成驱动电路损坏的主要原因之一。
2. 遵守固定上电顺序：先合逻辑电源，等待工控机启动与传感器自检完成，再合动力电源。反向通电可能造成浪涌冲击损坏主板。
3. 严格防止动力电池过放。电池单体电压降至安全阈值以下将造成永久损毁；长期闲置应保持半电储存。
4. 急停回路保持独立物理断电路径，使硬件在软件异常挂起时能够切断动力供电。
5. 完成线路改造或更换器件后，先使用万用表测量通路与绝缘阻抗，确认接线无误后再上电测试。

## 3.7 队内平台与资料

项目中的私有子模块（`Zvalley-resource-old/`）归档有三类受限资料：硬件手册、实录测试日志与内部培训讲义。具备权限的队员拉取仓库需包含子模块：

```bash
git clone --recurse-submodules https://github.com/RobotWorkShop-BigHeroX/RoboCupBook.git
git submodule update --init --recursive
```

私有资料仅对授权队员开放。电路原理图、底层固件协议与非公开接口参数应通过平台负责人核实获取。

### SDK 初步验证流程

1. 克隆官方 SDK 仓库，按照文档配置编译工具链与底层依赖库。
2. 运行单关节控制示例，验证指令下发与编码器状态读取。
3. 循环打印全部关节的编码器反馈，与实物实际角度进行比对。
4. 编写基础测试循环：依次读取 IMU 数据与关节角度，发送固定目标姿态。
5. 接入超时保护、角度软限幅与急停回调函数。保护机制未经确认前，严禁驱动真机关节运动。
