# 1 RoboCup介绍

> **面向新成员导读**  
> 欢迎来到 RoboCup 人形机器人足球联赛（Humanoid Soccer League, HSL）！本章将为你梳理 RoboCup 赛事的宏伟愿景、历史变革路线、当前核心竞赛规则以及至关重要的裁判系统（GameController），帮助你快速建立对赛事的整体认知。

## 1.1 涵盖有RoboCup的历史（尤其是HSL在近期的更改线路）

### 1.1.1 RoboCup 终极愿景与赛事演进
RoboCup（Robot World Cup，机器人世界杯）创立于 1997 年，其著名的长远科学目标是：**“到 2050 年中叶，开发一支完全自主的人形机器人足球队，战胜最近一届的人类男子足球世界杯冠军队。”**

为实现这一目标，RoboCup 设立了多个组别，经历近三十年的发展，赛事经历了从轮式、全向轮、标准平台到双足人形机器人的技术跃迁。

```
[初期阶段]                [多路线并行期]                      [终极集结期 (当前)]
轮式小型组 (SSL)   ───┐
轮式中型组 (MSL)   ───┼──> 标准平台组 (SPL - NAO) ───┐
双足类人组 (Humanoid) ─┘   3D/2D 仿真组 (Simulation) ──┼──> 【聚焦 Humanoid Soccer League (HSL)】
家庭服务组 (@Home) ─────── 家庭与物流挑战赛 ──────────┘     双足大/中/小人形全自主足球对抗！
```

### 1.1.2 关键变革路线（聚焦 HSL 战略收敛）
在近期的国际技术委员会（TC）与执行委员会（EC）战略调整中，RoboCup 赛事体系迎来了重大重组路线：
1. **合并 SPL（标准平台组）**：历史上采用 Aldebaran/SoftBank NAO 机器人的标准平台组（SPL）积累了三十年极其深厚的定位、视觉、队伍通信与多机器人战术决策经验。随着人形硬件的演进，SPL 逐步并入人形足球联赛大体系，其顶尖开源生态（如 B-Human）成为 HSL 的核心技术基石。
2. **取消 MSL（中型轮式组）**：轮式中型组曾在全向轮运动控制、超大范围全景视觉和高速射门上传承了丰富经验，但轮式运动与 2050 人形愿景存在本质断层。随着人形机器人动态平衡能力的成熟，MSL 逐步退出历史舞台。
3. **取消仿真组与 @Home 等周边分支的重心转移**：赛事委员会宣布进一步压缩仿真组（Simulation）及部分分散战线组别，集中全球顶尖高校与科研团队的研发精力，全量聚焦在 **真实物理世界中高动态、高不确定性的人形机器人足球对抗（HSL）**。

因此，**HSL 正在成为整个 RoboCup 乃至全球人形机器人技术对抗的皇冠明珠**。

## 1.3 对目前赛事规则简单的介绍

HSL 比赛是在标准人工绿茵草皮球场上进行的完全自主对抗比赛，所有决策、感知和运动控制必须在机器人本地机载计算机上独立运行。

```
┌────────────────────────────────────────────────────────┐
│                        足球场全景                       │
│  [球门A] ┌──────┬──────────────────────┬──────┐ [球门B] │
│          │禁区  │       中圈           │  禁区│         │
│          │      │         ○            │      │         │
│          └──────┴──────────────────────┴──────┘         │
└────────────────────────────────────────────────────────┘
```

### 1.3.1 核心赛制概览
- **赛制规模**：当前全面推进 **7人制标准（7 vs 7）**，对抗强度、场地覆盖要求与协同战术复杂度相比以往的 4v4/5v5 呈指数级上升。
- **比赛时长**：整场比赛分为上下半场，**半场有效时长通常为 10-15 分钟**（依具体组别赛程公布而定），中场休息 5-10 分钟。
- **换人与维修规则**：
  - 参赛队在死球、进球或裁判暂停时可向主裁判申请换人或将故障机器人移出场外维修（Pick-up）。
  - 离场维修的机器人需接受至少 30 秒的罚时，且重新入场时必须由裁判通过 GameController 发送指令并在己方底线规定位置回场，严禁擅自入场。
- **自主性严禁干预**：比赛开始后，除使用无线网络接收裁判盒指令外，**严禁任何人类队员远程遥控机器人**。

## 1.4 裁判盒的程序源码

### 1.4.1 GameController（裁判盒）工作原理
GameController（简称 GC）是整个 RoboCup 赛事的“神经中枢”。主裁判在场边通过电脑界面的 GC 发送比赛状态，GC 会通过本地局域网向场地内所有机器人的指定 UDP 端口广播状态数据包（RoboCupGameControlData）。

```
           ┌────────────────────────┐
           │  主裁判电脑 (运行 GC)   │
           └───────────┬────────────┘
                       │ UDP 广播 (端口 3838)
         ┌─────────────┴─────────────┐
         ▼                           ▼
┌──────────────────┐       ┌──────────────────┐
│  Robot 1 (我方)  │       │  Robot 2 (对方)  │
│  接收状态机解析  │       │  接收状态机解析  │
└──────────────────┘       └──────────────────┘
```

### 1.4.2 核心比赛状态流转
机器人的行为决策必须严格响应 GC 广播的五种核心状态：
1. **INITIAL（初始状态）**：机器人放置在场外，准备入场。
2. **READY（准备状态）**：机器人自主走向开球规定站位。
3. **SET（定位就绪）**：机器人就位静止，等待开球哨声。
4. **PLAYING（比赛进行）**：自由对抗，寻球、进攻、防守、射门。
5. **FINISHED（半场/全场结束）**：停止一切主动运动，进入待机阻尼。

此外还包括罚球点球（PENALTY SHOOT）、界外球、任意球以及黄牌/红牌罚下（PENALTY_MANUAL）等子状态。

### 1.4.3 源码获取与调试说明
- **官方仓库**：[RoboCup-HumanoidSoccerLeague/GameController](https://github.com/RoboCup-HumanoidSoccerLeague/GameController)
- **本地测试方法**：
  新成员在仿真器或本地机器上调试自主决策代码时，可以使用官方提供的 GameController 生成网络广播包，配合各队伍开源的 `game_controller_client` 驱动进行联合仿真联调。
- > [!TIP]
  > 比赛前请务必确认本队机器人配置的 Team Number 与 Player ID 与 GC 界面完全一致，否则机器人将拒收广播数据包！
