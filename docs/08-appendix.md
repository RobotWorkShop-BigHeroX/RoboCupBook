# 附录：参考手册与速查

## 附录 A 术语表

| 中文术语 | 英文 / 缩写 | 核心概念定义与解释 |
| :--- | :--- | :--- |
| **人形足球联赛** | HSL | RoboCup 下属的人形机器人足球联赛（Humanoid Soccer League），本书核心对象 |
| **标准平台组** | SPL | 统一使用 Aldebaran NAO 机器人的历史组别，现已合并融入人形体系 |
| **中型组** | MSL | 轮式全向底盘中型机器人组别，现已停办 |
| **技术说明文档** | TDP | 各参赛队每年必须提交的技术报告（Team Description Paper），包含系统方案与实验数据 |
| **裁判盒** | GC | 官方比赛状态广播控制程序（GameController），用于发布比赛计时与裁判指令 |
| **数据分发服务** | DDS | ROS 2 底层基于分布式发布/订阅机制的去中心化通信中间件标准 |
| **服务质量** | QoS | 规定消息传输可靠性（RELIABLE / BEST_EFFORT）、队列缓冲深度与保活机制的策略集 |
| **坐标变换** | TF2 | ROS 2 中维护空间中各个参考坐标系之间随时间变化的变换树组件 |
| **坐标变换树** | TF tree | 从地图坐标系（map）贯穿至机体（base）、传感器（camera）的空间树状拓扑 |
| **蒙特卡洛定位** | MCL | 基于粒子滤波算法，利用粒子群概率分布估计机器人全局空间位姿的方法 |
| **位姿粒子** | particle | MCL 定位中的基础假想状态单元，包含空间位置与航向角 $(x, y, \theta)$ 及对应权重 |
| **重采样** | resampling | 按照粒子权重分布重新抽样，剔除无效粒子并复制高置信度粒子的运算步骤 |
| **足式里程计** | odometry | 依靠关节编码器角度变化与触地开关状态推算得出的相对位移与速度估计 |
| **正运动学** | FK | 在已知各关节旋转角度的前提下，推算末端执行器（如脚掌）相对基坐标系的空间位置 |
| **逆运动学** | IK | 在已知脚掌期望落点位置的前提下，反向求解下肢各关节所需的转动角度 |
| **惯性测量单元** | IMU | 采集机器人本体三轴角速度与三轴加速度并解算机体动态姿态的惯性传感器 |
| **零力矩点** | ZMP | 地面反作用力的总合力矩水平分量为零的点，用于判定双足机器人的动态平衡裕度 |
| **压力中心** | CoP | 足底支撑区域所受地面反作用力垂直分量的等效作用点 |
| **有限状态机** | FSM | 包含有限数量离散状态及其流转触发事件的经典控制逻辑结构 |
| **行为树** | BT | 由 Fallback、Sequence 与条件/动作节点构成的层次化任务决策控制结构 |
| **仿真到真机** | sim2real | 将在物理仿真引擎中训练得到的控制策略无缝迁移并部署至物理真机平台的过程 |
| **域随机化** | domain randomization | 在仿真训练阶段人为随机扰动环境摩擦力、机体质量与通信时延，增强控制策略鲁棒性 |
| **机器人描述文件** | URDF | 基于 XML 格式规范描述机器人连杆质量、惯性张量、外观几何与关节限位的模型文件 |
| **推理加速引擎** | TensorRT / .engine | NVIDIA 针对特定 GPU 硬件架构编译量化的深度学习高性能推理引擎与权重文件格式 |
| **漏检** | false negative | 视野中客观存在目标物体（如足球），但视觉检测系统未能将其识别输出 |
| **误检** | false positive | 视野中客观不存在目标物体，但视觉检测系统产生错误识别并输出边界框 |

## 附录 B 新成员 90 天计划

本计划面向刚加入战队的新成员，按每周投入约 8 至 10 小时研发时间设计，目标在三个月内具备独立维护与验证单一功能模块的能力：

| 学习阶段 | 重点学习内容 | 阶段验收标准 |
| :--- | :--- | :--- |
| **第 1–2 周** | 精读第 1 章（赛制规则）与第 6 章（安全守则）；参与一次真机全流程测试 | 能够准确说明比赛状态机流转逻辑与三类安全应急停机操作 |
| **第 3–4 周** | 学习 Git 协作工作流与常用 Linux 调试命令；克隆代码仓库并在本地完成构建 | 能够独立提交包含规范格式信息的 PR，能够修改配置文件中的指定参数 |
| **第 5–6 周** | 学习第 4 章 ROS 2 核心机制；跑通本地 ROS 2 通信示例工程 | 能够绘制出机载软件核心节点的话题拓扑与 QoS 配置关系 |
| **第 7–8 周** | 跟随高年级队员参与真机联调；掌握 rosbag2 录包与离线回放 | 能够熟练使用 rosbag2 记录异常话题并在离线环境下复现定位故障 |
| **第 9–10 周** | 确定研发方向进组（感知组精读 4.5、策略组精读 4.6、运控组精读 3.2） | 能够在所负责模块中独立调整算法参数并解释测试现象产生的物理机制 |
| **第 11–12 周** | 独立承担小型开发任务（如补充特定视觉类别或增加行为树判断分支） | 完成从代码修改、仿真对比到保护吊架下的真机验证全流程 |

## 附录 C 故障排查速查

| 异常现象 | 优先排查点 | 常见故障根因 |
| :--- | :--- | :--- |
| **机器人完全不动作** | 裁判盒状态、硬件急停按钮、遥控器阻尼开关 | 比赛状态停留在 INITIAL；急停回路未复位；遥控手处于阻尼状态 |
| **无法接收裁判盒广播** | 机载配置队号、球员编号、局域网网段、系统防火墙 | 队号或球员 ID 配置不一致；广播端口 3838 被系统防火墙规则阻断 |
| **场地定位结果跳变** | 视觉标线特征数量、粒子群规模、重采样触发阈值 | 球场对称导致半场认反；视野内标线严重不足时频繁触发无效重采样 |
| **视觉检测不到足球** | 相机曝光时间、模型置信度阈值、图像输入分辨率 | 场地光照引起草皮反光过曝；训练数据集未包含当前色温光照条件 |
| **图像传输延迟过大** | 相机话题 QoS 配置、队列缓冲深度、机载 CPU 占用 | 视觉话题配置为可靠传输且队列深度过大，导致历史图像帧发生积压 |
| **双足步态发散失衡** | IMU 零偏扣除、关节机械零位对正、保护吊绳是否牵扯 | 未在上电静止期执行 IMU 零偏校准；保护吊绳过紧拉扯机体质心 |
| **关节转动出现机械异响** | 立即断电！手动轻转关节检查传动阻力 | 减速器行星齿轮损伤断齿；外部连杆发生形变与走线发生物理干涉 |
| **机器人行走轨迹向一侧偏斜** | 左右下肢对称关节机械零位、双侧脚底摩擦系数 | 左右髋关节旋转零位存在角度差；单侧橡胶脚垫磨损严重发生打滑 |
| **单腿起脚踢球打偏** | 髋部偏航旋转关节零位、球体相对相机坐标解算 | 髋部航向角存在机械偏差；坐标变换未考虑相机到机体的旋转矩阵 |
| **编译工程时提示报错** | 依赖库版本、环境变量是否加载（`source` 工作区） | 工作空间 setup.bash 未加载；第三方库版本与系统需求不匹配 |
| **合上动力电后系统无响应** | 动力电池端电压、急停回路导通状态、动力保险丝 | 动力电池组严重过放触发保护；急停按钮未旋转弹出；主回路保险丝烧断 |
| **机载网络出现间歇性丢包** | RJ45 工业网线水晶头、交换机端口、无线信道干扰 | 网线接头松动氧化；现场存在大量同频 Wi-Fi 信号造成严重无线信道拥堵 |

## 附录 E 队内黑话对照

| 常用术语 | 具体工程含义 |
| :--- | :--- |
| **上机 / 上真机** | 将编写的算法与控制策略部署至真实物理机器人硬件上运行（仿真环境运行不算） |
| **跑包** | 使用 ROS 2 的 rosbag2 工具回放此前实地录制的话题数据，进行算法离线验证 |
| **挂机** | 将机器人使用吊索安全悬挂在保护吊架下方，处于就绪但脚掌微悬空的受保护状态 |
| **进阻尼** | 触发控制程序将伺服电机切换至阻尼模式，关闭主动驱动力，保留阻尼缓冲（参见第 6 章） |
| **翻车** | 机器人失去动平衡发生摔倒，或算法出现异常退出导致整套流程中断 |
| **对零位** | 通过机械标定工装与标定软件，将所有关节伺服电机的机械零位与编码器零位校准一致 |
| **标场地** | 根据比赛现场特定的人工草皮颜色与场馆照明条件，现场重新微调相机的曝光与色彩阈值 |
| **踢空** | 视觉系统检测到了球体但空间坐标解算偏差较大，导致机器人摆腿踢球未能命中目标 |
| **追不上** | 上层决策系统输出了期望运动速度，但受限于底层步态加速度与防倾倒约束，物理机体无法跟上期望值 |
| **掉包** | 局域网网络通信拥堵或中间件配置不当，导致关键话题消息或裁判盒广播数据发生丢失 |
| **烧板子** | 电机伺服驱动板或电源管理板因带电插拔、短路、过压浪涌或长时间堵转而损毁 |
| **过检录** | 机器人的几何尺寸、全备重量、传感器合规性与电气安全指标全部通过技术委员会的严格审查 |
