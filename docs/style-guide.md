# RoboCupBook 写作规范

> 改编自 [Google 开发者文档风格指南](https://developers.google.com/style/highlights)（CC BY 4.0，2026-10-19 阅读版）。
> 只保留适用于本书的条款；标 **[中]** 的是中文或本书特有的补充。
> 本书读者：第一次进实验室、会一点 Python、没碰过 ROS 2 的本科生。

## 0 总则

**每句话要么给事实，要么给判断，要么给动作。三样都占不上，就删掉。**

判断标准：删掉这句话，读者会不会少知道一件事？不会，就删。

## 1 人称

- 用「你」称呼读者，不用「您」，全篇统一。 **[中]**
- 「我们」只能指 BigHeroX。不要把读者包进「我们」。 **[中]**
- 需要读者动手时用祈使句，省掉主语。

| 不推荐 | 推荐 |
| :--- | :--- |
| 让我们一起看看 ROS 2 的架构 | 下面看 ROS 2 的架构 |
| 本章将为你梳理……帮助你建立认知 | 你需要先知道场上谁在发指令 |

## 2 让动作有主语

被动语态和动词虚化是同一个病：看不出谁在做什么。中文里表现为「进行 / 实现 / 具有 / 具备 / 通过……的方式」。

| 不推荐 | 推荐 |
| :--- | :--- |
| 对步态参数进行优化 | 调步态参数 |
| 系统具备实时检测能力 | 系统每 33 ms 检测一帧 |
| 通过粒子滤波进行全局位置校正 | 用粒子滤波把位置拉回场地坐标 |
| 在 ROS 2 中通过标准话题接口进行订阅 | 订阅 `sensor_msgs/msg/Imu` 这个话题 |

## 3 条件在前

先写前提，读者不适用就可以跳过这句话。

| 不推荐 | 推荐 |
| :--- | :--- |
| 拍下 Stop 按钮，如果你需要急停 | 需要急停时，拍下 Stop 按钮 |
| 关闭电源，当机器人抖动时 | 机器人抖动时，先关电源 |
| 更多信息见 [链接] | 更多信息见 [链接] |

## 4 不预告

删掉章节开场三件套：**欢迎来到 / 本章将介绍 / 你将建立完整认知**。

- 章节第一句直接是内容，或者读者真实会问的问题。
- 不承诺「完整」「系统」「全面」——承诺不了。
- 也不要预告「后续将支持」「新版将改为」。等做完了再写。

## 5 不过度断言

- 禁用最高级：**最好 / 最强 / 最快 / 唯一 / 彻底 / 完全 / 零缺陷**。
- 慎用 **确保 / 保证**：说不出验证方法就不要写。
- 有数字就要有来源；没来源就写成待测，或者删掉。
- 评价其他队伍只写可查的事（名次、开源了什么），不写「代码质量最高」这类没有标准的排名。
- 可以说好话，**形容词不能代替证据**。

| 不推荐 | 推荐 |
| :--- | :--- |
| 首选 YOLO11（工程稳定性最好） | 队里现役模型是 YOLO11，TensorRT 工具链齐全 |
| 确保推理时延在 15 ms 以内 | 单帧超过 33 ms 就会丢帧（相机 30 fps） |

## 6 三种内容分开写

每条强结论都要能看出属于哪一类，必要时在句末标注：

- `[官方]` 规则原文、官方仓库 —— 给出处（Rules.tex 章节号、commit、发布日期）。
- `[本队实测]` 本队机器、本队代码 —— 给平台、日期、条件。
- `[建议]` 作者判断 —— 允许有立场，但要说理由。

不要把 `[建议]` 写成 `[官方]` 的语气。

## 7 术语

- 首次出现：中文（English, 缩写）；之后只用一种写法，不再中英混排。
- 全书统一，见下表，新增术语先加表再用。

| 统一用法 | 不要写 |
| :--- | :--- |
| 全局定位（自定位） | 自定位 / 全局定位 混用 |
| 裁判盒（GameController, GC） | 裁判系统 / 裁判盒 混用 |
| 阻尼模式 | 阻尼态 / 软态 |
| 足式里程计 | 腿部里程计 / 里程计 |

## 8 标题

标题给读者导航用；写成给自己记的备忘录，读者就看不懂。用名词短语或动作短语，不用「涵盖有……（尤其是……）」。

| 不推荐 | 推荐 |
| :--- | :--- |
| 1.1 涵盖有 RoboCup 的历史（尤其是 HSL 在近期的更改线路） | 1.1 组别是怎么一步步收缩到 HSL 的 |
| 1.3 对目前赛事规则简单的介绍 | 1.3 一场比赛怎么开始、怎么停、怎么换人 |

- 标题里不放链接、不放代码。 **[中]**
- 不用「概述」「简介」占位；写清楚这一节讲的是什么。

## 9 时间锚点

书会活很久，正文里的「目前 / 最新 / 即将 / 近期」三个月后就错了。

- 版本写进**文档属性或页眉**（「2026 赛季版」），不写进正文。
- 需要指版本时，指分支或文件名，不指「最新」。

| 不推荐 | 推荐 |
| :--- | :--- |
| 记得时刻拉取最新源码 | 以 `HSL-Rules` 仓库 `main` 分支为准（本书对应 2026 赛季） |
| 官方英文最新规则规范 | 官方规则源码 `Rules.tex` |

## 10 链接

- 链接文字说明去向，不写「点击这里」「详见此处」。
- 不把裸 URL 当正文句子。
- 仓库内文件用相对路径；**禁止 `file:///` 绝对路径**（Pages 和 PDF 里都会失效）。

## 11 列表与步骤

- 有先后顺序用编号，无顺序用项目符号。一条一步。
- 步骤里不写「简单」「容易」「只需」——读者卡住时这些话只会让人更挫败。
- 列表项尽量同构：都以动词开头，或都是名词短语，不要混。

## 12 [中] 中文排版

- 数字与单位之间加空格：`40 kg`、`12 ms`、`3.5 m`；数字与中文之间也加（`7 人制`）。
- 代码、文件名、命令行用 code font，不要用引号包。
- 每句尽量不超过 40 字，一个动作写一句。
- 不用「进行了一次……的操作」这类叠套；能一个动词说清就一个动词。
