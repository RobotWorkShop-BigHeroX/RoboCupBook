## 3.0 必学：Git

对于协同开发而言，版本控制是每个工程师的第一道基本功。

### 3.0.1 核心要求
1. **基础工作流**：熟练运用 `git status`、`git diff`、`git commit -m`、`git push`、`git pull --rebase`。严禁随意在公共分支进行 `git push --force`。
2. **分支管理模型**：掌握 Feature 分支规范，通过 Pull Request / Merge Request 进行代码审查与集成。
3. **子模块（Submodule）机制**：本项目将敏感手册存放在私有仓库并作为子模块引入。克隆本仓库时需使用递归命令：
   ```bash
   git clone --recurse-submodules https://github.com/RobotWorkShop-BigHeroX/RoboCupBook.git
   ```
4. **实践建议**：若是刚注册 GitHub 的新账号，建议自己新建几个仓库，编写简单的 YAML 工作流跑通 GitHub Actions，刷一刷 CI/CD 的自动化检查流程。

## 3.1 ros2

ROS 2 是现代机器人软件栈的行业标准骨架。在机器人足球系统中，重点掌握以下 8 大核心特性：

```
                      ROS 2 计算体系全景图
┌────────────────────────────────────────────────────────┐
│                   Node Composition                     │
│  ┌───────────────────────┐   ┌───────────────────────┐ │
│  │ Vision Component      │   │ Behavior Component    │ │
│  │ (零拷贝进程内共享内存) │   │ (生命周期统一管理)    │ │
│  └───────────┬───────────┘   └───────────┬───────────┘ │
└──────────────┼───────────────────────────┼─────────────┘
               ▼                           ▼
┌────────────────────────────────────────────────────────┐
│   ROS 2 Middleware: DDS (Data Distribution Service)    │
│   QoS 配置: Liveliness / Reliability / Durability      │
│   TF2 树维护 ◄─── 机体 / 相机 / 全局场地实时坐标映射   │
└────────────────────────────────────────────────────────┘
```

### 1. DDS / RTPS 通信中间件
- **思想本质**：抛弃了 ROS 1 的单点中心节点（roscore），底层采用工业级 OMG DDS（Data Distribution Service）标准，基于 RTPS 协议实现分布式无中心节点自发现。
- **足球应用**：即使场内某台机器人的工控机由于跌倒震动重启，也不会拖垮整个车队或局域网通信，自发现机制允许动态加入网络。

### 2. 节点与通信模型
- **Topic（话题）**：单向异步流式数据广播（如相机每秒 30 帧的图像流）。
- **Service（服务）**：同步双向请求-应答机制（如向运动控制器下发“复位关节”单次指令）。
- **Action（动作）**：带实时进度反馈、支持中途取消的长周期目标任务（如“倒地起身”、“移动至点球点”）。

### 3. QoS（服务质量策略）
- **核心策略**：
  - `Reliability`：`RELIABLE`（可靠传输，重传机制，用于关键比赛状态）vs `BEST_EFFORT`（尽力而为，低延迟，用于高频传感器）。
  - `Durability`：`TRANSIENT_LOCAL`（历史持久化，晚加入的节点也能收到最后一次发布的参数配置）。
  - `History` & `Depth`：队列缓冲深度。
- **足球应用**：IMU 和相机数据必须设为 `BEST_EFFORT` + `Depth=1`，丢弃过时数据保证实时性；裁判盒比赛状态必须设为 `RELIABLE`。

### 4. Executor（执行器）与回调调度
- **机制原理**：决定回调函数（Timer、Subscription 等）在哪个线程以何种优先级被唤醒。
  - `SingleThreadedExecutor`：单线程轮询，逻辑简单无锁，但耗时回调会阻塞控制周期。
  - `MultiThreadedExecutor`：多线程并行调度，高频控制需设置专属 `CallbackGroup`（如 `Reentrant` 或 `MutuallyExclusive`）。

### 5. Lifecycle Node（生命周期节点）
- **状态机控制**：`Unconfigured` $\to$ `Inactive` $\to$ `Active` $\to$ `Finalized`。
- **足球应用**：在裁判盒处于 `INITIAL` 或 `READY` 状态时，底层电机驱动节点可处于 `Inactive` 仅监听；一旦裁判哨声切至 `PLAYING`，一键批量激活（Active）所有感知与步态流水线。

### 6. Node Composition（节点组合）与进程内通信
- 将多个独立节点编译为动态链接库组件（Component），挂载到同一个容器进程（Container）中运行。
- **性能优势**：节点之间的数据传递通过指针实现**零拷贝（Zero-copy）**，极大节省图像和点云等巨量内存搬运开销。

### 7. TF2（坐标变换系统）
- **空间树构建**：管理机器人各连杆在时间维度上的坐标系树：
  $$\text{world} \longrightarrow \text{odom} \longrightarrow \text{base\_link} \longrightarrow \text{head\_link} \longrightarrow \text{camera\_link}$$
- **足球应用**：视觉在相机坐标系中检测到的足球坐标 $(x_c, y_c, z_c)$，通过 TF 树实时变换为机器人当前坐标系 $(x_b, y_b)$ 及场地全局坐标系 $(x_w, y_w)$。

### 8. rosbag2（数据录制与回放）
- **实车利器**：在真机对抗测试时录制所有关键话题。回到实验室后使用 `ros2 bag play` 100% 重现比赛场景，离线复现与排查丢球、误判和崩溃问题。

## 3.2 Linux

熟练的 Linux 命令行操作是机器人开发的日常肌肉记忆。

- **官方推荐自学平台**：[Linux Journey 在线教程](https://labex.io/LinuxJourney)
- **必备核心命令清单**：
  - 目录与路径：`pwd`（打印当前路径）、`ls -lh`（列表详情）、`cd`（切换目录）
  - 搜索与排错：`find . -name "*.urdf"`（文件搜索）、`grep -rn "QoS" .`（文本模式匹配）
  - 监控与追踪：`tail -f run.log`（持续追踪日志末尾）、`ps aux | grep ros`（检查进程是否存在）
  - 环境与编译：`source /opt/ros/.../setup.bash`（加载环境变量）、`git`（代码版本追踪）、`cmake`（跨平台编译构建）

## 3.3 视觉（YOLO11 与 YOLO26）

机器人足球在复杂光照和场地眩光下的目标提取依赖高效轻量的深度学习检测网络。

- **推荐版本选型**：
  - **YOLO11（最稳定生产版本）**：在嵌入式工控机（如 Orin Nano / Xavier）上拥有最成熟的 TensorRT 部署工具链和算子支持，首选用于比赛主力模型。
  - **YOLO26（最新实验版本）**：结构新颖，鼓励有算力和兴趣的队员开展前沿精度与速度对比实验。
- **主要用途**：
  - 足球检测（白色球体、黑白斑纹）
  - 球门立柱与横梁检测（白色立柱、门线交界）
  - 对方与友方机器人检测（根据腰间不同颜色的 Team Marker 色块识别队友与对手）
- **落地关键**：模型需通过 TensorRT 进行 FP16 / INT8 量化编译为 `.engine` 文件，确保推理时延控制在 15 ms 以内。

## 3.4 行为树和状态机（策略组 重点）

策略组的核心使命是：“在充满对抗与不确定性的赛场上，让 7 台机器人做出最合理的群体协作决策”。

```
                    行为树攻防顶层决策简图
                        ┌───────────┐
                        │ ? Fallback│
                        └─────┬─────┘
                ┌─────────────┴─────────────┐
                ▼                           ▼
        ┌───────────────┐           ┌───────────────┐
        │ 倒地检测与起身 │           │ → Sequence进攻│
        └───────────────┘           └───────┬───────┘
                               ┌────────────┴────────────┐
                               ▼                         ▼
                        ┌──────────────┐         ┌──────────────┐
                        │ 寻球与对位   │         │ 调整射门角度 │
                        └──────────────┘         └──────────────┘
```

1. **有限状态机（FSM / HFSM）**：适合处理严格互斥的底层状态流转（如裁判盒状态响应、单腿跌倒判定）。
2. **行为树（BehaviorTree.CPP）**：现代主流架构，具备极佳的模块化与可重用性。通过控制节点（Sequence、Fallback、Parallel）编排 Condition（是否看到球、是否处于进攻半场）与 Action（执行带球、向右横移、射门）。

## 3.5 粒子滤波算法（感知组 重点）

### 3.5.1 规则限制下的破局关键
> [!IMPORTANT]
> **官方竞赛规则硬性禁止在人形机器人上安装激光雷达（LiDAR）！** 同时，主动红外深度相机（如 RealSense D435）在阳光与绿茵场草皮反射下噪点极大，且在部分规则评审中存在合规争议。

因此，**机器人的全局自定位完全依赖机载单目/双目可见光相机与粒子滤波算法（MCL）结合！**

### 3.5.2 算法实现核心步骤
1. **粒子群初始化**：在场地坐标系中随机散布若干代表机器人可能位姿 $(x, y, \theta)$ 的粒子。
2. **运动预测（结合 TF2 与里程计）**：根据足式里程计的运动增量，更新每个粒子的位置。
3. **视觉特征提取**：利用图像检测算法提取场地特征点（白线交点 L 型/T 型角、中圈圆弧点、球门左右立柱柱脚点）。
4. **测量更新（权重重采样）**：对比观测特征与已知场地地图之间的几何偏差，给符合当前相机的粒子赋予高权重，淘汰低权重粒子。
5. **位姿输出并发布 TF**：粒子收敛后的均值即为机器人在全局地图中的绝对坐标，发布为 `map` $\to$ `odom` 的 TF 动态变换，消除里程计的累积漂移。

## 3.6 深度强化学习（不做任何要求，看个人能力）

对于对人形步态生成与端到端控制感兴趣的进阶队员，推荐以下知识演进路线：

1. **基础理论**：
   - **Bellman Optimization（贝尔曼最优方程）**：动态规划与值函数迭代基石。
   - **BOE / 动态规划**：状态价值 $V(s)$ 与动作价值 $Q(s, a)$ 关系。
   - **TD（时序差分学习）与蒙特卡洛（Monte Carlo）方法**：采样与时序回溯更新。
2. **经典网络与策略算法**：
   - **Policy Network（策略网络）**：直接输出动作概率分布。
   - **Actor-Critic（演员-评论家框架）**：价值网络指导策略网络收敛。
   - **Q-learning 与 DDPG（深度确定性策略梯度）**：连续动作空间下的确定性控制。
   - **PPO（Proximal Policy Optimization，近端策略优化）**：当前四足与双足机器人端到端步态学习中应用最广泛、最稳健的算法（如在 Isaac Gym / Zlab_Gym 中进行多刚体环境对抗训练）。
