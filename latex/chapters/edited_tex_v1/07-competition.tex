\section{第一次参赛：从报名到上场}

参赛工作除了日常技术研发，还涵盖资格材料审查、远途装箱运输、现场检录合规性裁决与紧凑的比赛日执行。之所以要将非技术流程制度化，是因为机器人足球是一项强工程依赖的实战联赛，硬件超重数公克、网口被防火墙阻断、甚至资格视频机位不合规，都会直接导致全队一年研发努力在检录阶段被一票否决。\official

\subsection{抵达赛场后的首日核验流程}

到达比赛场馆并布置好工位后，必须按顺序执行以下环境核验：

\begin{enumerate}[leftmargin=*]
    \item \textbf{赛场网络拓扑核验：} 接入赛场指定局域网，核对裁判盒广播网段与端口放行策略，确认机载系统与调试电脑之间 Ping 延迟稳定低于 5 毫秒且丢包率为零。
    \item \textbf{现场草皮与光照标定：} 在真实比赛草皮上测试相机曝光参数、白平衡与检测置信度。室内场馆顶灯色温与自然天光漫射与实验室存在显著偏差，必须就地微调相机曝光抑制高光反光。
    \item \textbf{裁判盒全链路联调：} 连接现场官方 GameController，完整测试 INITIAL、READY、SET、PLAYING 及各种罚时状态跳转，验证机载状态机是否准确响应。
    \item \textbf{全备物理尺寸预检录：} 借用现场检录工具，实测机器人直立高度、全备重量与足底投影面积。之所以要赛前自检，是因为若发现超重数百克，战队尚有充分时间打磨非承重结构件或更换轻量紧固螺栓。
\end{enumerate}

\subsection{现场调试三大纪律}

\begin{itemize}[leftmargin=*]
    \item \textbf{一次只改动一个参数。} 若同时改动步态抬腿高度与视觉检测置信度，当出现踢球失准时，根本无法分辨是由于足底打滑还是视觉识别迟缓，由此导致排查方向彻底混乱。
    \item \textbf{每次变更均做书面记录。} 详细记录改动发生时间、修改的代码位置、具体参数数值以及调整前后的物理表现差异。
    \item \textbf{保持随时可回退状态。} 修改代码前必须使用 Git 在本地建立提交，一旦微调未达预期，能够一秒恢复至上一个稳定版本。
\end{itemize}

\subsection{赛后复盘标准模板}

比赛结束后建议在当日完成结构化记录：
\begin{itemize}[leftmargin=*]
    \item \textbf{比赛关键失分点：} 丢球、视觉误判、定位混淆、决策死锁抑或电池欠压？
    \item \textbf{首次出现的异常物理现象：} 该现象此前在实验室测试中是否出现过征兆？
    \item \textbf{单点优化方案：} 若下一轮比赛仅允许修改一个参数或逻辑分支，应当聚焦于何处？
    \item \textbf{下一场赛前验证指标：} 下一轮上场前，必须在热身场地确切验证哪项动作？
\end{itemize}

\noindent 复盘结论必须对应到可观测的具体物理现象、分析推导的原因与可执行的测试动作，为后续算法迭代提供可靠依据。
